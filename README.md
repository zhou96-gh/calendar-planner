# 双平台日历

由 `holiday-planner-utools` 和 `desktop-calendar-todo` 合并，公共日历、调班、假期、农历与设置以 uTools 当前实现为准。两个原项目保留，本项目独立维护和发布。

## 结构

```text
index.html / src/app.js   两端共用页面和交互
src/holiday/             共用业务、离线历法入口与数据编解码
src/platforms/           uTools 与 Tauri 存储和生命周期适配
src/desktop/             待办、窗口控制、桌面外观及完整备份
src-tauri/               Windows 原生壳、逐字段 SQLite 与恢复机制
themes/ / assets/        共用配色和图片
tests/                   共用行为与平台适配测试
```

公共功能包括周末半天与周期、调休补班、日期修正、月统计、独立节日、年度参考额度、下一年预加载和分批预热。官方安排只参与法定安排计算，节日由随包离线历法计算。

设置页通过顶部 Tab 切换外观、周末设置和节假日数据；桌面版额外提供“桌面挂件”Tab。Tab 栏贴顶并铺满宽度，正文单独保留内边距；表单与说明等内容块的间隔基准为 16px，字段标签与控件为 8px，均与其他间距一起按窗口及密度比例调整。支持左右方向键、Home 和 End 切换，不使用头部标题栏或左侧目录；通过悬浮按钮返回日历，加载状态放在节假日数据分区。

离线历法使用 `lunar-javascript`，MIT 许可证随 uTools 安装目录和 Windows 绿色版一起分发。

桌面端保留待办、待办日期角标、拖动拉伸、锁定、尺寸恢复、托盘、单实例、开机启动、字号、亮度和透明度。桌面扩展不会出现在 uTools 插件中。

外观设置提供全局排版“紧致 / 宽松”，所有上下左右留白、内边距与项目间距均按原始比例统一调整，包括设置页面。窗口缩小时使用共同的弹性比例，紧致模式在此基础上统一乘 .85；日期格和图标按钮保留既有宽高比例，普通控件不额外压缩高度，字号不变。主页面板按内容收拢，uTools 保留原有日期左右排版，双列侧栏占满页面可用高度并保留外边距；Windows 保留顶部导航与等高附着窗口。两端日历、设置、弹窗及桌面附着窗口同步生效。

uTools 页面最小宽度按正常日期格、左右导航、侧栏和实际间距共同计算，日期格按宽松 84px、紧致 71.4px 预留空间，不再按更小的日期格压低最小宽度。两种密度均保留右侧栏位置，统计栏与主体按同一组宽度对齐。页面最小高度至少覆盖摘要、日历和外边距；侧栏使用右侧普通列布局，随页面一起滚动，不固定或吸顶。侧栏内部独立滚动，高度占满视口可用空间并保留外边距，最小高度跟随日历，至少延伸到日历底部。视口小于内容所需的最小尺寸时，保留右列及页面滚动，不移到日历下方。尺寸限制只作用于插件页面，不改变宿主窗口或启动方式。

调班弹窗按完整时间范围表单加内边距确定宽度和最小宽度，两种密度均保持 32px 的日期、时段控件高度。开始、结束始终同排，不随视口缩小而分行或产生表单横向滚动；弹窗高度随内容调整，过矮时纵向滚动。

桌面版沿用共享日期格的文字与标签布局，首次启动使用最小尺寸，之后记住手动调整的大小；最小窗口宽度为 680px，页面适应实际内容区宽度，日历外层和内部留白以 8px 为基准同比例调整，日期格随窗口宽度均匀分配。顶部同一行提供侧栏、设置、固定及退出按钮。待办与调班数量显示在对应 Tab，调班记录一行一条。

侧栏每次启动默认收起，顶部两个按钮分别控制两个独立附着窗口：选中日期、待办和调班默认在左，节日与假期默认在右，窗口贴合间距统一为 2 个逻辑像素。工作区空间不足时只调整新打开窗口的位置，不改变用户已经拖动选择的方向。可分别拖动各窗口标题选择贴在主窗口左侧或右侧；标题获得焦点后也支持左右方向键选择。主窗口移动、拉伸时附着窗口自动跟随；关闭按钮或 Escape 仅收起所在附着窗口。主窗口统一计算和保存数据，附着窗口只显示同步视图，待办和调班编辑表单继续在主窗口打开。

滚动区域隐藏滚动条并保留滚动和原生拉伸。字号偏移应用于日期数字和桌面控件，农历、节日名称沿用 uTools 的 10px。

## 数据

uTools 保留原 `holiday-planner-state-v7` 存储键和 v7 假期交换格式。桌面存储使用程序同目录 `calendar-planner.db`，不会读取或覆盖旧项目 `desktop-calendar.db`。新项目不自动迁移旧数据库，可在桌面“完整备份”中显式导入旧桌面 v11 JSON；导入会替换公共设置、调班、假期和桌面待办，新桌面完整备份为 v12。

普通“导入假期安排”只替换涉及年份的假期和日期修正；独立配色导入只改变配色。桌面完整备份导入不改变原生窗口位置、锁定和开机启动设置。两平台各自保存数据，不自动同步。

保存使用串行快照，原生保存确认后才发布状态和提示成功；读取失败禁止覆盖原存储。自动加载结果不能覆盖后来导入或重置的数据。参考假期不保存为官方安排，也不导出。

## 开发和验证

标准环境为 Docker Compose；不需要连接外部数据库。

```bash
docker compose run --rm test
docker compose run --rm check
docker compose run --rm build
docker compose run --rm native-test
```

首次需要构建环境时执行 `docker compose build`。开发页面使用 `docker compose up dev`，端口以 Compose 配置为准。

## 打包

```bash
npm run build:offline
npm run build:web
npm run build:windows
```

uTools 独立安装目录为 `dist/utools/`，直接交付目录，不压缩；Windows 桌面前端为 `web-dist/`，绿色版输出到 `dist/windows/`。不在 `dist` 根目录额外放包。Windows 构建脚本把共享代码和原生壳复制到 Windows 临时目录，使用已安装的 Rust MSVC、C++ Build Tools 和 npm 缓存离线构建。不要直接打包项目根目录或从 WSL UNC 编译。

日常修改继续构建桌面前端和 uTools 插件；Windows 绿色包只在明确要求时生成。
